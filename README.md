# 30-Day Liver & Weight Reset
แอปภาษาไทยสำหรับ iPhone ช่วง 21 กันยายน–20 ตุลาคม 2026 ใช้ HTML + CSS + Vanilla JavaScript ไม่มี backend, framework, analytics หรือ CDN

## รุ่น 2 — ผู้ช่วยถามตอบและอาหารที่กินจริง
กดปุ่ม **✦ ผู้ช่วยอาหารและสุขภาพ** เหนือหน้าหลัก ใช้ภาษาไทยพิมพ์หรือใช้ไมค์บนคีย์บอร์ด iPhone ได้

นี่คือผู้ช่วยแบบกฎ/คำสั่งในเครื่อง **ไม่ใช่ AI ออนไลน์หรือโมเดลภาษา** ไม่ส่งข้อความออกไป ไม่ใช้ API key ไม่วิเคราะห์ภาพอาหาร และไม่สามารถเข้าใจภาษาธรรมชาติได้ทุกแบบ หากอ่านไม่ครบจะไม่บันทึกโดยเดา

### ตัวอย่างข้อความ
- `กินอะไรดี` — แสดงแผนของวันที่เลือก พร้อมยอดที่กินจริงแล้วและมื้อที่ยังไม่มีบันทึก
- `ไข่ต้ม 2 ฟองได้ไหม` — ประเมินค่าประมาณและยอดหลังเพิ่ม ยังไม่บันทึกอาหารจากคำถาม
- `บันทึกมื้อเย็น ไข่ต้ม 2 ฟอง กับ อกไก่ 100 กรัม` — สร้างรายการรอยืนยัน
- `มื้อเช้ากินกะเพราไก่ไข่ดาว 1 จาน แล้วก็ ทอดมันสองชิ้น` — แปลจำนวนเป็นค่าประมาณและให้ตรวจยืนยัน
- `โปรตีนถึงรึยัง` / `น้ำตาลเกินไหม` — เทียบรายการจริงกับเป้าหมายที่ตั้งไว้
- `บันทึกน้ำหนัก 65.5` / `ตั้งก้าว 8,450` — แสดงค่าเดิมและค่าใหม่ ให้กดยืนยันก่อนเปลี่ยน
- `DAY 2 บันทึกน้ำหนัก 65.5` — ระบุวันที่ในโปรแกรม
- `แก้ไขอาหาร` — แนะนำเปิดรายการอาหารเพื่อแก้ไข/ลบ
- `สรุปวันที่เลือก` / `สถิติสะสม` / `ออกกำลังอะไรดี`

ไม่ระบุวัน = วันที่เลือกบนหน้าจอ; “วันนี้/เมื่อวาน” ใช้วันที่จริงของเครื่อง; DAY 1 หรือ วันที่ 1 ของแผนคือ 21 ก.ย. 2026 ถ้าวันที่อยู่นอกโปรแกรม แอปไม่เปลี่ยนเป็นวันอื่นแทน ก่อนวันที่ 21 ก.ย. ให้ถามแบบไม่ระบุ “วันนี้” เพื่อดูแผนวันแรก

แชตเก็บ 120 ข้อความล่าสุดในเครื่องและใน JSON สำรอง แสดง 60 ข้อความล่าสุด คำสั่งรอยืนยันไม่ถูกเก็บเมื่อ refresh และไม่เปลี่ยนข้อมูลจนกดยืนยัน การส่งคำถามใหม่ยกเลิกคำสั่งที่รอยืนยันเดิม

### อาหารจริงและข้อมูลโภชนาการ
1. เปิดหน้าอาหาร → **บันทึกอาหารจริง** → เลือกเมนูมาตรฐาน หรือกรอกฉลากเอง
2. ตรวจชื่อ มื้อ ปริมาณ พลังงาน โปรตีน คาร์บ ไขมัน และน้ำตาลรวม ก่อนยืนยัน
3. ค่าทั้งหมดในแบบฟอร์มเป็น **ยอดของปริมาณที่กินจริง** หากกิน 2 หน่วยและฉลากระบุต่อ 1 หน่วย ต้องคูณก่อนกรอก
4. เมนูมาตรฐาน 18 รายการเป็นค่าประมาณ ไม่มีการผูกกับยี่ห้อสินค้าในร้านสะดวกซื้อ สูตร/ขนาด/น้ำมันและซอสทำให้ต่างได้ ฉลากจริงมีความสำคัญกว่า
5. ไม่ทราบคาร์บ ไขมัน หรือน้ำตาลให้เว้นว่าง ไม่ใช่กรอก 0 ระบบไม่สรุปว่า “ไม่เกิน” หากน้ำตาลบางรายการยังไม่ทราบ
6. การเลือกชื่ออาหารโดยไม่บอกปริมาณจะใช้หน่วยมาตรฐานที่แสดงในรอยืนยัน เช่น อกไก่ 1 ชิ้น = สมมติ 100 กรัม ต้องตรวจให้ตรงชิ้นจริงก่อนยืนยัน
7. ติ๊ก “กินแล้ว” ในเช็กลิสต์เดิมยังไม่เพิ่มยอดสารอาหาร เพราะไม่ได้ยืนยันเมนูและปริมาณจริง; การบันทึกอาหารจริงที่ระบุมื้อจะติ๊กมื้อนั้นให้ แต่ลบรายการแล้วไม่ลบเช็กลิสต์เดิมอัตโนมัติ
8. เมื่อกรอกทุกมื้อและเครื่องดื่มครบ ให้ติ๊ก **ฉันบันทึกอาหาร/เครื่องดื่มครบทั้งวันแล้ว** การเพิ่ม/แก้/ลบรายการทำให้ต้องยืนยันครบวันใหม่

### เป้าหมายและการเตือน
- โปรตีนเป้าหมายและเกณฑ์น้ำตาลรวม **เริ่มต้นเป็นว่าง** ให้ตั้งตามแพทย์/นักกำหนดอาหารเอง ไม่มีการเดาจากน้ำหนักหรือแคลอรี
- เกณฑ์น้ำตาลในแอปคือ **น้ำตาลรวม** ไม่ใช่น้ำตาลเติมหรือ free sugars จึงไม่ตั้ง 25/30 กรัมให้โดยอัตโนมัติ และไม่เอาเกณฑ์เหล่านั้นมาเทียบผิดประเภท
- หลังบันทึก จะแสดงการเตือนพลังงาน >700 kcal และน้ำตาลที่ทราบเกินเกณฑ์ พร้อมสถานะโปรตีน
- ถ้ายืนยันอาหารครบวันแล้วแต่ <500 kcal จะเตือนให้ตรวจความครบและปรึกษาผู้ดูแลแผน ไม่ยินดีหรือให้รางวัลกับการกินน้อยลง
- ถ้ากินเกิน ไม่แนะนำอดมื้อถัดไป ไม่หักแคลอรีออกกำลังจากอาหาร และไม่เพิ่มเซ็ตออกกำลังชดเชย ใช้แผนกิจกรรมเดิมตามแพทย์และอาการของวันนั้น
- เลือกเวลาเตือนให้สรุปประจำวันได้ เตือนในหน้าแอปวันละหนึ่งครั้งตามเวลาในเครื่อง หากเลยเวลาแล้วจะเตือนเมื่อเปิดแอปกลับมาในวันนั้น
- **ไม่มี push notification เมื่อปิดแอป/ล็อกหน้าจอ** ไม่ขอสิทธิ์แจ้งเตือน ระบบนี้ทำงานเฉพาะหน้าเว็บที่เปิดอยู่ โปรแกรมก่อนเริ่ม/หลังจบไม่เตือน
- การเอ่ยอาการหน้ามืด ใจสั่น เจ็บหน้าอก ฯลฯ ในแชต จะให้หยุดออกกำลังและติดต่อแพทย์ ไม่แนะนำออกกำลังเพิ่ม

### สถิติสะสม
หน้า **ความคืบหน้า** มีช่วง “ตั้งแต่เริ่ม” และ “7 วันล่าสุด” นับถึงวันนี้ ไม่รวมวันอนาคต
- ยอดพลังงาน โปรตีน และน้ำตาลที่ทราบจากทุกรายการที่บันทึก พร้อมจำนวนรายการที่ไม่ทราบน้ำตาล
- ค่าเฉลี่ยพลังงาน/โปรตีน เฉพาะวันที่ยืนยันอาหารครบวัน ไม่เอาช่องว่างมาคิดเป็นศูนย์
- ค่าเฉลี่ยน้ำตาล เฉพาะวันที่ยืนยันครบและทราบน้ำตาลทุกรายการ พร้อมจำนวนวันที่ใช้หาร
- จำนวนวันครบที่ถึงโปรตีนเป้าหมาย และจำนวนวันที่ยอดน้ำตาลที่ทราบเกินเกณฑ์
- กราฟอาหารจริง: สีเข้ม=ครบวัน สีจาง=ยังไม่ครบ ขีดเทา=ไม่มีข้อมูล
- ส่งออก CSV ครบ 30 วันพร้อมคอลัมน์ complete_day และ sugar_unknown_entries; ไม่ได้สรุปว่าค่าว่าง=0

### อัปเดตจากรุ่นเดิม
Export JSON สำรองก่อน จากนั้นแทนที่ไฟล์ index.html และ sw.js หรืออัปโหลดชุด ZIP ใหม่ลง repository เดิม ใช้ URL/เบราว์เซอร์เดิม เปิดออนไลน์เพื่อรับรุ่นใหม่

ยังใช้ localStorage key เดิม `liver-reset-v1` และ export version 1 เพื่อรับไฟล์สำรองเก่าได้ โดยเพิ่ม `smart.version=2`, `smart.proteinTarget`, `smart.sugarLimit`, `smart.messages`, การเตือน และ `days[].intake`, `days[].intakeClosed`

ไฟล์เก่าจะถูกเพิ่มฟิลด์ใหม่โดยไม่ลบน้ำหนัก ก้าว เช็กลิสต์ เป้าหมาย หรือรูป IndexedDB ไม่แปลงมื้อที่เคยติ๊กไว้เป็นยอดสารอาหารเพราะไม่ทราบสิ่งที่กินจริง Import JSON รุ่นเดิมจะไม่มีประวัติอาหารจริง/แชตที่เพิ่มในรุ่นใหม่ เพราะกู้คืนตามไฟล์นั้น; รูปเก็บตามกติกา Import เดิม

### ขอบเขตการทดสอบรุ่น 2
ตรวจด้วย Node/DOM จำลอง: ย้ายข้อมูลเดิม, แปลงจำนวนไทย/กรัม, คำสั่งรอยืนยัน, ไม่บันทึกซ้ำเมื่อยืนยันซ้ำ, ไม่บันทึกเมนูไม่รู้จักบางส่วน, ไม่ถือค่าน้ำตาลว่างเป็นศูนย์, สถิติและวันอนาคต, JSON roundtrip, validation, การ render 6 หน้า ×30 วัน และ Workout Circuit/Rest เดิม ผ่านแล้ว

ยังไม่ได้ทดสอบบน Safari/iPhone จริงหรือยืนยัน IndexedDB, layout, service worker และ download dialog ในเบราว์เซอร์จริง โปรดใช้ไฟล์สำรองและทดสอบกับข้อมูลทดลองก่อนใช้งานต่อเนื่อง

อ้างอิงความแตกต่างของ free sugars และน้ำตาลธรรมชาติ: https://www.who.int/news/item/04-03-2015-who-calls-on-countries-to-reduce-sugars-intake-among-adults-and-children

## เริ่มใช้งาน
เปิด index.html ในเบราว์เซอร์ได้โดยไม่ต้องติดตั้ง dependency หน้าแผนใช้ตั้งน้ำหนักเริ่มต้น น้ำหนักเป้าหมาย น้ำ และการนอน น้ำหนักเป้าหมายเริ่มต้น = น้ำหนักเริ่มต้น −7 กก. และแก้ไขได้

ไฟล์เดี่ยวใช้ฟังก์ชันติดตามได้ แต่การเปิด file:// บน iOS อาจเป็นหน้าพรีวิวแทน Safari และการเก็บข้อมูลขึ้นกับเบราว์เซอร์ แนะนำเปิดผ่าน GitHub Pages HTTPS เพื่อใช้จริงและ PWA

## โครงสร้าง
```text
liver-reset/
  index.html               # แอปทั้งหมด รวม CSS/JavaScript
  manifest.json            # ข้อมูล PWA (ไม่จำเป็นต่อการใช้ไฟล์เดี่ยว)
  sw.js                    # ออฟไลน์ผ่าน HTTPS/localhost
  README.md
  images/
    README.md              # รายชื่อภาพ JPG เสริมทั้งหมด
    icon-192.png
    icon-512.png
    [ภาพอาหารและออกกำลัง .jpg เป็นตัวเลือก]
```
รูปอาหารและออกกำลังกายเป็น placeholder ที่ออกแบบไว้ พร้อมชื่อและ emoji; ยังไม่แนบภาพถ่ายหรือภาพท่าจริง เพิ่มตาม path ใน images/README.md ได้ ถ้ารูปหายหรือโหลดไม่ได้ หน้าแอปไม่เสีย

## Deploy ด้วย GitHub Pages
1. สร้าง repository เช่น `liver-reset` บน GitHub (บัญชีทั่วไปใช้ public repository สำหรับ Pages)
2. แตก ZIP แล้วอัปโหลด **เนื้อหาด้านใน** ให้ index.html, manifest.json, sw.js และ images อยู่ที่ root ของ repository ไม่ซ้อนในโฟลเดอร์ liver-reset อีกชั้น
3. Commit ลง branch `main`
4. เปิด Settings → Pages → Build and deployment → Source: **Deploy from a branch**
5. เลือก branch `main` และ folder `/(root)` แล้ว Save
6. รอ deploy สำเร็จ แล้วเปิด URL ที่ GitHub แสดง ปกติเป็น `https://USERNAME.github.io/liver-reset/`
7. เปิดหน้าแผน รอข้อความ **พร้อมใช้ออฟไลน์ ✓** ก่อนทดลองปิดอินเทอร์เน็ตและเปิดเว็บใหม่

ไม่มี build command หรือ npm install ข้อมูลสุขภาพและรูปของผู้ใช้ไม่ได้อัปโหลดไป repository ห้ามอัปโหลดไฟล์ JSON สำรองส่วนตัวลง public repository

เอกสาร GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Add to Home Screen บน iPhone
1. เปิด URL HTTPS ของแอปใน **Safari**
2. แตะปุ่ม **แชร์** แล้วเลือก **เพิ่มไปยังหน้าจอโฮม (Add to Home Screen)**
3. หากมีตัวเลือก **Open as Web App** ให้เปิด แล้วแตะ **เพิ่ม**
4. เปิดแอปจากไอคอนใหม่ รอโหลดครั้งแรกให้ครบ
5. เริ่มบันทึกในช่องทางนี้เป็นหลัก เพราะ Safari, Home Screen, โหมดส่วนตัว หรือ URL คนละ origin อาจใช้พื้นที่ข้อมูลต่างกัน ใช้ Export/Import เพื่อย้ายข้อมูล

## ฟังก์ชันและวิธีนับ
- หน้า Today เลือกวันก่อนหน้า/ถัดไปได้ ปฏิทินหน้าแผนเปิดแก้ได้ครบ 30 วัน
- Daily score 8 รายการเท่ากัน (12.5% ต่อรายการ แสดงผลปัดจำนวนเต็ม)
- ชั่งน้ำหนักสำเร็จเมื่อมีน้ำหนักในวันนั้น และก้าวสำเร็จเมื่อ >=8,000; ทั้งสอง checkbox อิงค่าจริงที่กรอก จึงไม่เปิดให้ติ๊กแยก
- มื้ออาหาร หน้า Today และหน้าอาหารใช้ checkbox ชุดเดียวกัน
- ก้าวกรอกเอง ไม่เชื่อมกับ Apple Health: >=8,000 ถึงเป้าหมาย, >=10,000 ยอดเยี่ยม; แถบเต็มที่ 10,000
- น้ำหนักล่าสุด = ค่าที่กรอกในวันที่มากที่สุด หากยังไม่มีใช้ starting weight หากกรอกวันอนาคตค่าล่าสุดจะรวมวันนั้นด้วย
- เส้น target trend ลากจาก starting weight วันที่ 1 ถึง target วันที่ 30 เป็นแนวอ้างอิง ไม่ใช่การทำนาย
- Progress ring คือวันปฏิทินที่มาถึง/30 (รวมวันนี้) ไม่ใช่คะแนนกิจกรรม ก่อนเริ่มแสดง 0% หลังจบ 100%
- Days remaining = 30 ลบวันที่มาถึง (ไม่รวมวันนี้เป็นวันที่เหลือ)
- Days completed/Workout/Meal compliance ใช้เฉพาะวันเริ่มถึงวันนี้ ตัดวันอนาคตออก Meal compliance = มื้อที่ติ๊ก ÷ (จำนวนวันดังกล่าว ×3)
- Average steps = ค่าเฉลี่ยเฉพาะวันที่กรอกจนถึงวันนี้ รวมค่าศูนย์ ไม่นับช่องว่าง
- Badge −2/−4/−5/−7 กก. อิงน้ำหนักล่าสุด และอาจหายหากน้ำหนักขึ้น
- แผน 7 วันหมุน 4 สัปดาห์ แล้ววันที่ 29–30 ใช้ A/B และเมนู 1/2

## แผนอาหารและความปลอดภัย
**แผนพลังงาน 500–700 kcal/วันเป็นแผนที่ผู้ใช้ได้รับจากแพทย์ ไม่ใช่คำแนะนำสำหรับบุคคลทั่วไป**

เมนูตัวอย่างในแอปมี 3 มื้อ/วัน ค่ารวมประมาณ:
| วันรอบ | kcal | โปรตีน (กรัม) |
|---|---:|---:|
| 1 | 640 | 99 |
| 2 | 650 | 94 |
| 3 | 665 | 106 |
| 4 | 630 | 85 |
| 5 | 660 | 108 |
| 6 | 660 | 103 |
| 7 | 670 | 93 |

ทุกวันอยู่ในช่วงที่ระบุและไม่มีวันต่ำกว่า 500 kcal **ค่าทั้งหมดเป็นประมาณการ ไม่ใช่การรับรองสารอาหารครบถ้วน** น้ำหนักอาหารเป็นอาหารสุก/พร้อมกินและไม่รวมน้ำมันเติม ต้องให้แพทย์หรือนักกำหนดอาหารตรวจเมนู โปรตีน สารอาหารที่จำเป็น การติดตามอาการ และความหนักของการออกกำลังกายก่อนใช้เป็นแผนจริง การกินพลังงานต่ำมากควรอยู่ภายใต้การดูแลเฉพาะบุคคล เป้าหมาย 7 กก. ไม่ใช่ผลลัพธ์ที่รับประกัน และชื่อแอปไม่ใช่คำกล่าวอ้างรักษาไขมันพอกตับ

หากมีอาการหน้ามืด ใจสั่น เจ็บหน้าอก อ่อนแรงผิดปกติ ให้หยุดออกกำลังกายและติดต่อแพทย์ ถ้าเจ็บหน้าอกหรืออาการรุนแรง โทร 1669

ข้อมูลอ้างอิงด้านการดูแลแผนพลังงานต่ำมาก: https://www.nhs.uk/conditions/obesity/treatment/

## ข้อมูลและสำรอง
- localStorage key: `liver-reset-v1` เก็บ version, startDate, settings, days[30]
- daily fields: date, weight, breakfastComplete, lunchComplete, dinnerComplete, workoutComplete, steps, waterComplete, sleepComplete
- weight/steps ที่ยังไม่กรอกเป็น null; วันที่อยู่ในรูป YYYY-MM-DD
- IndexedDB `liver-reset-photos`, object store `photos`, keys `before`/`after`
- รูปย่อด้านยาวเหลือไม่เกิน 1200px แปลง JPEG คุณภาพ .82 และเก็บไว้เฉพาะเครื่อง การเลือก HEIC ขึ้นกับตัวถอดรหัสของเบราว์เซอร์ หากอ่านไม่ได้ใช้ JPG/PNG/ภาพหน้าจอ
- Export JSON รวมรูปเป็น data URLs; Import ตรวจ schema, ช่วงวันที่, ค่าตัวเลข และชนิดภาพก่อนเขียน พร้อมให้ยืนยันทับข้อมูล
- นำเข้าไฟล์ไม่มี photos จะเก็บรูปเดิม; ถ้ามี photos จะใช้ชุดรูปในไฟล์นั้น รวมถึง null ที่หมายถึงไม่มีรูป
- ล้างข้อมูลต้องยืนยันสองครั้ง ลบทั้งบันทึกและรูป
- ข้อมูลไม่ได้เข้ารหัสเพิ่มเติม ปกป้องเครื่องและไฟล์สำรองของคุณ
- การ refresh ปกติไม่ reset ข้อมูล แต่ล้างข้อมูลเว็บไซต์ โหมดส่วนตัว เปลี่ยนโดเมน เปลี่ยนเครื่อง หรือระบบคืนพื้นที่ อาจทำให้ข้อมูลหาย ควร Export ประจำ
- หาก localStorage เต็ม/ถูกบล็อกจะแสดงคำเตือน อย่าปิดหน้าก่อนส่งออก

## Offline และอัปเดต
PWA ต้องใช้ HTTPS หรือ localhost; file:// ไม่มี service worker ครั้งแรกต้องออนไลน์และไฟล์หลักกับไอคอนครบ เมื่อแสดงพร้อมออฟไลน์แล้ว cache จะมี app shell ภาพ JPG เสริมจะ cache หลังเคยเปิดดูสำเร็จเท่านั้น placeholder ใช้ได้ตลอด ภาพ Before/After ไม่ผ่าน service worker

เมื่อแก้ไฟล์และ deploy เวอร์ชันใหม่ ให้เปลี่ยน VERSION ใน sw.js เช่น liver-reset-v3 เปิดออนไลน์ใหม่เพื่อรับอัปเดต การอัปเดต cache ไม่ล้าง localStorage/IndexedDB

## การทดสอบ
ตรวจ JavaScript และ service worker syntax, JSON manifest, ช่วงวันที่ครบ 30 วัน, ค่าแคลอรีทุกวัน, สูตรคะแนน/น้ำหนัก, การบันทึกและโหลดกลับด้วย storage จำลอง, การ render 5 หน้า ×30 วันใน DOM จำลอง, Circuit 3 รอบ, เวลาพัก 45 วินาที, การทำ workout จบ, การตรวจ schema และ JSON roundtrip ผ่านแล้ว

ข้อจำกัดการทดสอบ: สภาพแวดล้อมนี้ไม่มี browser binary และดาวน์โหลด Chromium ไม่สำเร็จ จึงยังไม่ได้ทดสอบ layout ใน browser จริง, IndexedDB/รูป, download/import dialog, service worker offline หรือ Safari/iPhone จริง การตรวจจำลองไม่ทดแทนการทดสอบในเครื่องจริง

ก่อนใช้จริง: ตั้งค่าน้ำหนักและติ๊กกิจกรรม → refresh ดูว่าคงอยู่ → เลือกรูป → Export → เก็บไฟล์สำรองแล้วทดลอง Import → รอพร้อมออฟไลน์แล้วปิดเน็ตเปิดเว็บใหม่ → ตรวจบน Home Screen อีกครั้ง
